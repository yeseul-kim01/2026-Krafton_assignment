# 12. 스택 - 괄호 짝 맞추기

## 구현 내용

스택(LIFO)을 사용해 괄호 문자열이 올바르게 짝지어져 있는지 판별.

- `is_valid_parentheses(s)`: 스택 풀이
- `is_valid_parentheses_simple(s)`: 카운팅(+1/-1) 풀이

## 공부하면서 이해한 것

### 1. 이 문제가 스택과 어울리는 이유

괄호는 `(`가 들어오면 한 개씩 쌓이고, `)`가 오면 가장 최근에 들어갔던 `(`를 제거하면 되는 구조다. "가장 최근 것부터 제거"가 곧 LIFO(Last In First Out)이므로 스택이 자연스럽다.

실패 판정은 두 군데서 일어난다.

- 순회 중: `)`가 왔는데 스택이 비어 있으면 짝이 될 `(`가 없다는 뜻 -> 즉시 False
- 순회 후: 스택에 `(`가 남아 있으면 닫히지 않은 괄호가 있다는 뜻 -> False

```python
stack = []
for i in s:               # 인덱스가 필요 없어서 s 자체로 순회 (변수 낭비 없이)
    if i == '(':
        stack.append(i)   # 여는 괄호는 push
    elif i == ')':
        if not stack:     # 짝이 될 '('가 없음
            return False
        stack.pop()       # 가장 최근의 '(' 제거
    else:
        continue          # 괄호가 아닌 문자는 무시
if stack:                 # '('가 남아 있으면 미완성
    return False
return True
```

else의 continue는 조건에 없어도 항상 넣어주는 게 좋다. "괄호 외 문자는 의도적으로 무시한다"는 것이 코드에 드러난다.

### 2. 스택 구현: list vs deque

- 스택은 list로도, collections.deque로도 구현 가능
- list: append, pop (끝에서만) -> 스택으로 충분
- deque: append, pop에 더해 popleft 등 양쪽 조작 가능 -> 큐까지 커버
- 이 문제는 끝에서만 넣고 빼면 되므로 list로 충분

파이썬과 C의 차이: 파이썬 list는 할당될 때 크기가 자동으로 늘어나고 pop 하면 자동으로 관리되지만, C는 malloc으로 메모리를 할당하고 free로 해제해야 한다.

### 3. 스택 없이 푸는 방법 - 카운팅 풀이

이 문제는 사실 스택 없이도 풀 수 있다. 괄호 종류가 `()` 하나뿐이라 "무엇이 쌓였는지"를 기억할 필요가 없고 "몇 개 쌓였는지"만 세면 되기 때문.

```python
count = 0
for char in s:
    if char == '(':
        count += 1
    elif char == ')':
        count -= 1
        if count < 0:      # 스택 풀이의 "빈 스택에서 pop" 과 같은 상황
            return False
return count == 0          # 스택 풀이의 "스택이 비었는가" 와 같은 확인
```

- 카운팅 풀이의 장점: 메모리 사용량. 스택은 최악의 경우 O(N) 공간을 쓰지만 카운팅은 변수 하나로 O(1)
- 스택 풀이의 장점: 직관적이고, 확장에 강함. `(){}[]`처럼 괄호 종류가 여러 개면 "마지막에 연 괄호가 무엇인지"를 알아야 해서 카운팅으로는 불가능하고 스택이 필요해짐
- 두 풀이는 구조가 일대일 대응함: push = +1, pop = -1, 빈 스택 pop = count < 0, 마지막 빈 스택 확인 = count == 0

### 4. 자료구조 선택 이야기

실무에서는 상황에 맞는 자료구조 선택이 중요하다 (queue, stack, linked list, tree, graph 등).

- queue (FIFO): 들어온 순서대로 처리해야 하는 상황 -> 요청 처리 등
- stack (LIFO): 최근 것을 먼저 처리해야 하는 상황 -> 함수 호출(콜 스택), 표현식 평가, 실행 취소(undo) 등

## 실행 결과

```
입력: (())
결과: True

입력: (()
결과: False

입력: ()(())
결과: True

입력: ())(
결과: False
```

### 스택 상태 변화 추적

테스트 케이스 3 `"()(())"` -> True

| 단계 | 문자 | 동작 | 스택 상태 |
|---|---|---|---|
| 1 | ( | push | ['('] |
| 2 | ) | pop | [] |
| 3 | ( | push | ['('] |
| 4 | ( | push | ['(', '('] |
| 5 | ) | pop | ['('] |
| 6 | ) | pop | [] |
| 끝 | | 스택 비어 있음 | True |

테스트 케이스 2 `"(()"` -> False (순회 후 실패)

| 단계 | 문자 | 동작 | 스택 상태 |
|---|---|---|---|
| 1 | ( | push | ['('] |
| 2 | ( | push | ['(', '('] |
| 3 | ) | pop | ['('] |
| 끝 | | '(' 가 남음 | False |

테스트 케이스 4 `"())("` -> False (순회 중 실패)

| 단계 | 문자 | 동작 | 스택 상태 |
|---|---|---|---|
| 1 | ( | push | ['('] |
| 2 | ) | pop | [] |
| 3 | ) | 빈 스택에서 pop 시도 | 즉시 False |

케이스 4는 마지막 `(`를 보기도 전에 3단계에서 바로 종료된다. 전체 개수만 세면 `(` 2개 `)` 2개로 같지만 순서가 틀렸다는 것을 "count < 0" 또는 "빈 스택 pop"이 잡아낸다.

## 더 알아볼 것
