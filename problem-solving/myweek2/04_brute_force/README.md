# 04. 완전 탐색 - 두 수의 합 찾기

## 구현 내용

배열에서 합이 target이 되는 모든 인덱스 쌍 (i, j) 찾기 (i < j). 정석인 이중 반복문 풀이와, 딕셔너리(해시)를 이용한 one-pass 풀이 두 가지.

## 이 문제를 왜 냈을까

완전 탐색은 모든 최적화의 기준선이다. 이 문제(two sum)는 "일단 O(N^2)으로 다 확인"에서 출발해서 해시로 O(N)까지 내려가는, 자료구조로 시간을 사는 대표적인 사례라서 출제된 것 같다. 단, 이 문제는 조건이 하나 특이하다.

- 값이 아니라 인덱스 쌍을, 하나가 아니라 전부 출력해야 함
- 인덱스 출력 제한이 걸려 있어서, 값 기준으로 변환(정렬 등)하는 풀이는 인덱스를 따로 보존해야 하는 비용이 생김. 그래서 이 조건에서는 완전 탐색이 오히려 자연스러운 정석 풀이가 됨

## 풀이 1: 이중 반복문 (정석)

```python
for i in range(n):
    for j in range(i + 1, n):    # j를 i+1부터: i < j 유지로 중복 방지
        if nums[i] + nums[j] == target:
            pairs.append((i, j))
```

- 내부 반복을 i+1부터 시작하는 것만으로 (j, i) 중복과 (i, i) 자기 자신 쌍이 원천 차단됨
- 시간 O(N^2), 추가 공간 O(1)

## 풀이 2: 딕셔너리(해시) one-pass (채택)

```python
seen = defaultdict(list)             # 값 -> 그 값이 나온 인덱스들
for i, num in enumerate(nums):
    for j in seen[target - num]:     # 지금까지 나온 것 중 보수(target-num)였던 인덱스들
        pairs.append((j, i))
    seen[num].append(i)              # 자기 자신은 검사 후에 등록 (자기 쌍 방지)
```

- 아이디어: num을 보는 순간 필요한 상대는 target - num으로 정해져 있음. "그 값을 지금까지 어디서 봤는지"를 딕셔너리가 O(1)에 답해줌
- seen의 값을 리스트로 둔 이유: 같은 원소가 여러 개일 때 그 인덱스를 전부 보존해야 하기 때문. nums = [1, 1, 1, 1], target = 2면 (0,1), (0,2), (0,3), (1,2), (1,3), (2,3) 전부가 답이라서, 값 하나당 인덱스 하나만 저장하면 답이 누락됨
- 등록을 검사 후에 하므로 항상 j < i가 보장됨

## 효율 비교

| 풀이 | 시간 | 공간 | 비고 |
|---|---|---|---|
| 이중 반복문 | O(N^2) | O(1) | 답 개수와 무관하게 모든 쌍 확인 |
| 해시 one-pass | O(N + K) | O(N) | K = 답의 개수. 정렬 불필요 |
| 정렬 + 투 포인터 | O(N log N) | O(N) | (값, 인덱스)로 묶어 정렬 필요. 중복 원소 처리 조건이 추가로 필요 |

- 투 포인터도 가능하지만, 인덱스 출력 조건 때문에 원소 값과 인덱스를 쌍으로 묶어 정렬해야 하고, 같은 원소가 여러 개일 때의 처리도 따로 해야 해서 이 문제에서는 해시 쪽이 깔끔함
- 시간은 해시가 압도적이지만 공간 O(N)을 씀. "메모리를 써서 시간을 산다"는 트레이드오프
- 최악 케이스 주의: [1,1,1,1], target=2처럼 모든 쌍이 답이면 K = N(N-1)/2라서 어떤 풀이든 출력만으로 O(N^2)

## 실무에서

target - num을 키로 조회하는 "보수 찾기" 패턴은 캐시 조회, 두 테이블 조인(한쪽을 해시로 만들어놓고 다른 쪽을 스트리밍), 로그에서 매칭되는 이벤트 쌍 찾기 등에서 그대로 쓰인다.

## 실행 결과

```
배열: [2, 7, 11, 15]
목표 합: 9
결과 쌍: [(0, 1)]

배열: [1, 3, 4, 2, 5, 6]
목표 합: 7
결과 쌍: [(1, 2), (3, 4), (0, 5)]

배열: [1, 1, 1, 1]
목표 합: 2
결과 쌍: [(0, 1), (0, 2), (1, 2), (0, 3), (1, 3), (2, 3)]
```

참고: 해시 풀이는 쌍이 "나중 인덱스(i) 기준"으로 나온다. 이중 반복문이면 테스트 2가 (0,5), (1,2), (3,4) 순서가 됨. 문제는 "모든 쌍"만 요구하므로 순서는 무관.

## 더 알아볼 것

- [ ] three sum으로 확장 (정렬 + 투 포인터가 표준이 되는 이유)
