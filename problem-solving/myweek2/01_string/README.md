# 01. 문자열 - 회문(Palindrome) 판별

## 구현 내용

대소문자 무시, 공백/특수문자 제거 후 회문인지 판별. 풀이를 세 가지로 시도.

## 이 문제를 왜 냈을까

회문 판별 자체는 한 줄짜리 문제다. 진짜 포인트는 두 가지라고 본다.

1. 지저분한 입력을 정규화(normalize)하는 전처리 - 대소문자 통일, 불필요한 문자 제거. 실무에서 검색어 매칭, 중복 데이터 판정, 사용자 입력 검증을 할 때 항상 먼저 하는 작업이 정확히 이 패턴이다
2. 파이썬다운 도구 선택 - 같은 O(N)이라도 슬라이싱/filter/컴프리헨션 중 뭘 쓸지

## 세 가지 풀이

### 풀이 1: 반으로 나눠서 비교

전체 문자열의 공백/특수문자를 지운 후 반으로 나누고, 뒷부분을 뒤집어 앞부분과 동등 연산자로 비교. 길이가 홀수면 중간 글자는 비교에서 제외 (혼자라서 짝이 필요 없음).

```python
s = ''.join(e for e in s if e.isalnum()).lower()
len_s = len(s)
if len_s % 2 == 0:
    return s[:len_s//2] == s[len_s//2:][::-1]
else:
    return s[:len_s//2] == s[len_s//2+1:][::-1]
```

### 풀이 2: 전체 뒤집어 비교 (채택)

```python
s = ''.join(filter(str.isalnum, s)).lower()
return s == s[::-1]
```

filter(function, iterable)는 iterable의 각 요소에 function을 적용해 True를 반환하는 요소만 걸러낸다. str.isalnum을 함수 객체 그대로 넘기는 게 핵심.

### 풀이 3: 람다 버전

```python
s = ''.join(filter(lambda x: x.isalnum(), s)).lower()
return s == s[::-1]
```

풀이 2와 로직은 같지만, 람다는 호출마다 파이썬 함수 호출 한 겹을 더 거친다. str.isalnum을 직접 넘기면 C 레벨에서 돌아서 미세하게 더 빠르다.

## 효율 비교

| 풀이 | 시간 | 공간 | 비고 |
|---|---|---|---|
| 1. 반쪽 비교 | O(N) | O(N) | 비교 횟수는 절반이지만 빅오는 동일 |
| 2. filter + [::-1] | O(N) | O(N) | 가장 짧고, 슬라이싱이 C 레벨이라 실측도 빠른 편 |
| 3. lambda | O(N) | O(N) | 풀이 2보다 함수 호출 오버헤드만큼 손해 |

- 셋 다 정제 O(N) + 비교 O(N)이라 시간 복잡도는 같고, 정제된 문자열을 저장하느라 공간도 O(N)으로 같다
- 반쪽 비교가 "비교 연산을 절반으로 줄였다"는 점에서 아이디어는 좋지만, 상수 배 차이는 빅오에 안 잡히고 코드만 길어졌다. 짧은 풀이 2가 낫다고 판단

### 또 다른 풀이: 투 포인터

정제된 복사본을 안 만들고 양 끝에서 포인터 두 개로 중앙까지 좁혀가면 추가 공간 O(1)로 풀 수 있다 (비교 중 알파벳/숫자가 아닌 문자는 건너뛰기). 문자열이 아주 클 때(파일 단위 등) 복사본을 만들기 부담스러우면 이 방식이 유리하다.

## 실행 결과

```
입력: "A man, a plan, a canal: Panama"
회문 여부: True

입력: "race a car"
회문 여부: False

입력: "Was it a car or a cat I saw?"
회문 여부: True

입력: " 1 "
회문 여부: True
```

테스트 4가 좋은 엣지 케이스: " 1 "은 정제하면 "1"이 되고, 길이 1짜리 문자열은 뒤집어도 자기 자신이라 True. 정제 결과가 빈 문자열이어도 "" == ""라 True가 되는데, 이게 맞는 스펙인지는 문제 정의에 따라 다르다.
