# 16. 퀵 정렬 (Quick Sort)

## 구현 내용

분할 정복(Divide and Conquer) 방식의 퀵 정렬. 피벗(pivot)을 기준으로 왼쪽/오른쪽을 나누어 재귀적으로 정렬한다.

- `partition(arr, low, high)`: 마지막 원소를 피벗으로 잡고, 피벗보다 작거나 같은 원소는 왼쪽으로 보낸 뒤 피벗을 제자리에 놓고 그 인덱스를 반환
- `quick_sort_helper(arr, low, high)`: 재귀 함수. `low < high`일 때만 분할하고 양쪽을 재귀 정렬
- `quick_sort(arr)`: 진입점

## 공부하면서 이해한 것

### 1. 전체 흐름

정렬되지 않은 배열을 피벗 기준으로 분리한다. 피벗보다 작은 원소는 왼쪽으로, 큰 원소는 오른쪽으로 이동한다. 그러면 피벗은 자기 최종 위치에 확정되고, 남은 왼쪽/오른쪽 구간에 같은 작업을 재귀적으로 반복한다.

### 2. partition에서 i의 역할

```python
pivot = arr[high]
i = low - 1          # i는 작은 원소들의 마지막 인덱스를 추적
for j in range(low, high):
    if arr[j] <= pivot:
        i += 1
        arr[i], arr[j] = arr[j], arr[i]
arr[i + 1], arr[high] = arr[high], arr[i + 1]
return i + 1         # 피벗의 최종 위치 인덱스 반환
```

- i는 "피벗보다 작거나 같은 원소 구역의 오른쪽 끝"을 추적한다. 아직 작은 원소가 하나도 없으니 low - 1에서 시작
- j가 순회하다가 작은 원소를 만나면 i를 한 칸 늘리고 그 자리로 교환 -> 작은 원소 구역이 한 칸 확장됨
- 순회가 끝나면 i까지가 전부 피벗 이하이므로, 피벗을 i + 1과 교환하면 피벗이 정확히 제자리에 감
- 반환값 i + 1이 피벗의 최종 위치. 이 인덱스는 이후 재귀에서 다시 건드리지 않는다

### 3. 재귀 구조와 base case

```python
if low < high:
    pi = partition(arr, low, high)
    quick_sort_helper(arr, low, pi - 1)    # 피벗 왼쪽
    quick_sort_helper(arr, pi + 1, high)   # 피벗 오른쪽
```

- base case: `low >= high`이면 구간에 원소가 1개 이하라서 이미 정렬된 상태 -> 아무것도 안 하고 종료
- 피벗 자신(pi)은 재귀 범위에서 제외한다. 이미 제자리이기 때문
- 머지 정렬과 달리 별도의 병합 단계가 없다. partition이 "제자리에서" 나누는 순간 정렬이 진행되기 때문

## 재귀 호출 시각화 - quick_sort([10, 7, 8, 9, 1, 5])

실제 실행을 추적한 결과. #번호는 호출 순서, 들여쓰기는 재귀 깊이.

```
#1 qs(low=0, high=5) 구간=[10, 7, 8, 9, 1, 5]  pivot=5
   partition 후: [1, 5, 8, 9, 10, 7]  pi=1  (5가 인덱스 1에 확정)
  #2 qs(low=0, high=0) 원소 1개 [1]        -> base case 종료
  #3 qs(low=2, high=5) 구간=[8, 9, 10, 7]  pivot=7
     partition 후: [7, 9, 10, 8]  pi=2      (7이 인덱스 2에 확정)
    #4 qs(low=2, high=1) 빈 구간            -> base case 종료
    #5 qs(low=3, high=5) 구간=[9, 10, 8]  pivot=8
       partition 후: [8, 10, 9]  pi=3       (8이 인덱스 3에 확정)
      #6 qs(low=3, high=2) 빈 구간          -> base case 종료
      #7 qs(low=4, high=5) 구간=[10, 9]  pivot=9
         partition 후: [9, 10]  pi=4        (9가 인덱스 4에 확정)
        #8 qs(low=4, high=3) 빈 구간        -> base case 종료
        #9 qs(low=5, high=5) 원소 1개 [10]  -> base case 종료
```

- quick_sort_helper 총 호출 횟수: 9회 (partition은 4회)
- 배열 전체의 변화: [10,7,8,9,1,5] -> [1,5,8,9,10,7] -> [1,5,7,9,10,8] -> [1,5,7,8,10,9] -> [1,5,7,8,9,10]
- 관찰: 이 배열은 피벗(마지막 원소)이 계속 작은 값이라 왼쪽 구간이 거의 비고 오른쪽으로만 쏠린다. 분할이 반반으로 안 되는, 최악에 가까운 모양

## 실행 결과

```
=== 테스트 케이스 1 ===
정렬 전: [10, 7, 8, 9, 1, 5]
정렬 후: [1, 5, 7, 8, 9, 10]

=== 테스트 케이스 2 ===
정렬 전: [64, 34, 25, 12, 22, 11, 90]
정렬 후: [11, 12, 22, 25, 34, 64, 90]

=== 테스트 케이스 3: 중복 원소 ===
정렬 전: [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]
정렬 후: [1, 1, 2, 3, 3, 4, 5, 5, 5, 6, 9]

=== 테스트 케이스 4: 이미 정렬됨 ===
정렬 전: [1, 2, 3, 4, 5]
정렬 후: [1, 2, 3, 4, 5]
이미 정렬된 경우 O(n²) 시간 소요 (최악의 경우)
```

## 시간 복잡도

| 경우 | 복잡도 | 이유 |
|---|---|---|
| 평균 | O(N log N) | 분할이 대체로 반반에 가깝게 됨 |
| 최악 | O(N^2) | 이미 정렬된 배열 + 마지막 원소 피벗 -> 매번 한쪽이 통째로 남음 |

테스트 케이스 4가 최악 케이스인 이유: [1,2,3,4,5]에서 피벗 5를 잡으면 왼쪽에 4개가 전부 남고, 다음엔 피벗 4에 3개가 남고... 분할이 전혀 안 되어 재귀 깊이가 N이 된다.

## 더 알아볼 것

- [ ] 피벗을 랜덤/중앙값으로 골라 최악 케이스를 피하는 방법 (median-of-three)
- [ ] 퀵 정렬이 불안정 정렬(unstable)인 이유 - 같은 값의 상대 순서가 바뀔 수 있음
- [ ] 파이썬 내장 sorted()가 퀵 정렬이 아니라 Timsort를 쓰는 이유
