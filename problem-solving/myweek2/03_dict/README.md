# 03. 파이썬 문법 - 리스트와 딕셔너리 활용

## 구현 내용

학생 정보(딕셔너리)의 리스트에서 평균 점수와 평균 이상인 학생 이름 리스트를 구함.

## 이 문제를 왜 냈을까

"리스트 안에 딕셔너리" 구조는 실무 데이터의 기본 모양이다. API가 주는 JSON 응답, DB에서 읽어온 레코드 목록이 정확히 `[{"name": ..., "score": ...}, ...]` 형태다. 이 구조에서 집계(평균)하고 조건으로 거르는(필터) 작업은 실무에서 매일 하는 일이고, 파이썬으로는 제너레이터 표현식과 리스트 컴프리헨션이 그 표준 도구다. SQL로 치면 집계 후 조건 필터 - AVG 구하고 WHERE/HAVING으로 거르는 패턴과 같다.

## 풀이

```python
all_scores = sum(s['score'] for s in students)   # O(N)
average = all_scores / len(students)
above_average_students = [s['name'] for s in students if s['score'] >= average]
```

- 딕셔너리는 키가 인덱스가 아니다. `students[0]['score']`처럼 리스트 인덱스로 학생을 고르고, 키('score')로 값에 접근해야 함
- sum(...) 안의 `s['score'] for s in students`는 제너레이터 표현식이라 중간 리스트를 안 만들고 바로 합산함 (대괄호로 감싼 리스트 컴프리헨션과의 차이)
- 평균 이상 필터는 리스트 컴프리헨션으로: 조건(`if s['score'] >= average`)에 맞는 학생의 이름만 추출

## 왜 두 번 순회하는가

sum으로 한 번, 필터로 한 번 순회해서 O(2N)이지만 빅오로는 O(N). 한 번의 순회로 합치고 싶어도 불가능하다 - 평균은 전체를 다 봐야 나오는 값이라, 평균을 알기 전에는 누가 평균 이상인지 판정할 수 없기 때문. "집계 결과에 의존하는 필터는 두 패스가 필요하다"는 구조 자체가 이 문제의 포인트.

## 반올림에 대한 고민

소수점 몇 자리인지에 대한 정보가 문제에 없어서 round(average, 2)를 고민하다가 원값을 반환하기로 함. 테스트 2에서 81.66666666666667이 그대로 출력되는 이유. 계산값은 그대로 두고 표시할 때만 f"{avg:.2f}"로 다듬는 쪽이 안전하다 - 반올림한 값으로 뒤에서 다시 계산하면 오차가 누적되기 때문에, 반올림은 최종 출력 단계에서 하는 게 원칙.

## 실행 결과

```
평균 점수: 87.5
평균 이상 학생: ['Bob', 'David']

평균 점수: 81.66666666666667
평균 이상 학생: ['Frank', 'Grace']
```

- 테스트 1: (85+92+78+95)/4 = 87.5, 87.5 이상은 Bob(92), David(95)
- 테스트 2: (70+85+90)/3 = 81.67, Frank(85), Grace(90)
